# Milestone report: overrides (014)

**What landed.** `ResolveOptions.overrides?: readonly string[]`, and so `LoadOptions.overrides`. In `resolveEntry`, after the chain walk and before the graph is built, `readOverrides` reads each text as a config-authored reference anchored at the entry's phantom span — classified against the entry document, offered to `locate` for a scheme the library does not own, read by `readAtTarget` — refuses a `$`-prefixed root key as `override-reserved-key`, and never touches the `GraphBuilder`. `Graph` gains an additive optional `overrides`; `buildGraph` takes a third argument; `deriveLayers` pushes each override as a `role: "config"` layer after the entry; `finalizeWithDelegation` walks each override for delegation as it walks the entry. `ReferenceKind` gains `"override"`. `resolve()` passes the option; `generateTypes()` passes `undefined`. Everything downstream — demands, `final`, `append`, provenance, `why()` — is unchanged code doing what it already did over one more layer.

**Conformance.** Five resolve-conformance cases (`overrides-used`, `-ordered`, `-located`, `-reserved-key`, `-unreachable`) with hashes derived by `sha256sum` over the fixture bytes, and sixteen unit tests through `load()`, `why()` and `generateTypes()` with the in-memory host. Written before the code: thirteen of the sixteen were red against the unchanged library, and the three green ones were green for a nameable reason — they assert v1.5 behaviour with the option absent, empty, or handed to `generateTypes()`, which is the freeze rule itself. The corpus file refused to load at all until the code existed, because the new diagnostic code was not in the catalogue. Two sabotages, each backed up to the scratchpad first: with `readOverrides` skipping every text, 18 tests went red; with the overrides read but `deriveLayers` never pushing them, 10 went red, every one in the override suite, and the reserved-key and unreachable cases stayed green because they refuse before the fold. Restored; `grep -rn SABOTAGE src/ tests/` is empty. Full suite: 89 files, 2079 tests, green; `tsc --noEmit` clean.

**Documents.** `SPEC.md` Article VI gains a law, §15 the entry, §14's exporter moves from v1.6 to v1.7 on the precedent of the four displacements before it. `README.md` gains the milestone row, a paragraph under the host seam, and a preamble that now counts to v1.6 — it had stopped at v1.4 while the table already carried v1.5, which is a small drift this milestone corrects in passing. `package.json` 1.5.0 → 1.6.0.

## Found, recorded rather than smoothed

- **The repository forbids call-site spreads under `src/`, by a test, and the first draft had two.** `diagnostics.push(...parsed.diagnostics)` is the form V8 limits to about 125,000 arguments, and `tests/unit/validate-totality.test.ts` sweeps the tree for it. Replaced with the `extend` helper the codebase already has. Worth knowing before the next milestone rather than after its first full run.
- **`pnpm install` under pnpm 12 writes a `pnpm-workspace.yaml` prompting for build approval.** It is not repository content and was deleted before committing. A `.gitignore` line or a pinned pnpm would stop it recurring; neither is this milestone's call.
- **Two design choices an implementer had to make, both stated in the option's doc comment so they are found by reading.** An override's text is read relative to the entry document's directory, not the working directory, on the launching schema's precedent — "as if the entry had named it" is the one sentence that needs no second rule. And every override is read even after one fails, so a command line with two bad flags reports both; the alternative, stopping at the first, would have made the operator fix flags one run at a time.
- **An override is `role: "config"`, not a fourth role.** Principle VI asks whether the distinction is semantic. The fold reads no strategy from a config layer and provisions fill what it leaves silent, and both are exactly what an override wants; rank already says which config outranks which. The one place that picks *the* config — `directiveDiagnostics`'s subject for `$`-directive demands — still finds the entry first, and an override has no directives by construction. If a consumer ever needs to ask "was this value the operator's?", `Layer.identity.location` answers it today, and a `role: "override"` would be the addition to make then, not now.
- **Delegation breadcrumbs from two configs share one map.** Breadcrumb keys are per-graft origin ids minted by a counter, so an entry and an override delegating at the same key produce two entries and the fold's replace rule decides which value ships; `why()` on the winner finds the winner's breadcrumb. Not a defect, but the first time two config-role documents have delegated in one resolution, and stated here so the next reader does not rediscover it.
- **A remote override is untested.** `readAtTarget` handles the `https` branch and a recorded-transport case could pin it, but no consumer names a remote override and the milestone did not invent one. The code path is the same one `$adopts` has exercised since v0.2.
- **The milestone folder is one `spec.md` and this report**, on 012's and 013's precedent. The governance question 012 raised — whether every addition needs the seven-file flow — is still open and still not an implementer's to decide.

## Questions for Egildo

1. **The name.** `overrides` shipped, with the append caveat written into Article VI's law. `amendments` described the semantics better and collided with BelType's own `amend`, which carries run facts that are not configuration. If the word is wrong, the rename is one option field, one `ReferenceKind` member, one code, and the documents.
2. **Should an override be allowed to carry `$pin`?** Today any `$`-key is refused. A pinned override makes no sense for a minted command line, but a `-c ci.yaml` an organization ships might want to say which bytes it expects. Refused now under "ship the restriction"; reopening it is a sentence in FR-005.
3. **Whether `Graph.overrides` should be a required field with an empty default.** Optional kept every hand-built graph in the suite unchanged, at the cost of `?? []` at two consumers. A required field is the cleaner type and a larger diff.
